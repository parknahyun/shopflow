# 계약: REST API (골격)

각 사용자 스토리가 자기 API 섹션을 이 문서에 추가한다(ADR-0008 후속). 정해진 값은 [설정값 문서](../../../docs/configuration.md)를 가리킨다.

## 공통 규칙

- **경로**: 모든 API는 `/api` 아래에 둔다. 웹훅은 `/webhooks/payments`([payment-gateway-port.md](payment-gateway-port.md)).
- **노출 범위**: 어노테이션을 붙인 리포지토리만 읽기용으로 노출한다. 쓰기는 정해진 동작 경로로만 한다(`PUT`, `PATCH`, `DELETE`, 일반 `POST` 거절). 재고, 배송, 멱등키, 변경 이력, 환불 계좌는 목록에 없다.
- **외부 식별자**: 응답과 경로에는 `public_id`만 쓴다. 내부 식별자와 비밀번호 해시는 내보내지 않는다.
- **읽기 전용 프로젝션**: 응답은 필요한 필드만 담은 읽기 전용 프로젝션이다.
- **링크**: 관련 리소스와 가능한 동작은 링크로 안내한다.
- **인증과 권한**: 로그인하지 않은 요청은 로그인으로 보낸다. 고객 전용, 판매자 전용, 운영자 전용 기능을 역할로 나눈다. 상태를 바꾸는 요청은 사이트 간 요청 위조 방어 토큰이 필요하다.
- **멱등키 헤더**: 돈과 재고에 영향을 주는 동작은 `Idempotency-Key` 헤더를 받는다. 같은 키와 같은 내용은 저장된 결과를 그대로 돌려준다.

## 오류 응답

본문은 `{ "code": "...", "message": "한글 안내" }`이며 프론트엔드는 `code`로 화면 문구를 고른다.

| 상태 | 코드 | 언제 |
|------|------|------|
| 401 | `UNAUTHENTICATED` | 로그인하지 않음 |
| 403 | `FORBIDDEN` | 역할이 맞지 않음 |
| 404 | `NOT_FOUND` | 없는 개체, 또는 권한 없는 접근(존재 여부를 알리지 않는다) |
| 405 | `METHOD_NOT_ALLOWED` | 허용되지 않는 요청 방법 |
| 409 | `NOT_ALLOWED_TRANSITION` | 허용되지 않는 상태 변경 |
| 422 | `IDEMPOTENCY_KEY_REUSED`, `VALIDATION_FAILED` | 같은 멱등키에 다른 내용, 입력값 오류 |
| 422/409 | `IDEMPOTENCY_IN_PROGRESS` | 같은 요청이 처리 중 |
| 500 | `INTERNAL_ERROR` | 서버 오류 |

- US2 상품 탐색: 해당 스토리에서 추가
- US3 장바구니, 주문, 결제: 해당 스토리에서 추가
