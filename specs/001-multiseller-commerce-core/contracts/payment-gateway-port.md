# 계약: 결제 포트와 웹훅

도메인 코드는 결제 대행사(토스페이먼츠)를 직접 부르지 않고 `PaymentGateway` 포트만 쓴다. 운영 구현은 대행사 API를 호출하고, 테스트 구현은 가짜 응답을 돌려준다.

## 포트 동작

| 동작 | 입력 | 출력 | 설명 |
|------|------|------|------|
| `prepare` | 주문 공개식별자, 금액, 결제 방식, 멱등키 | 결제창 접속 정보 또는 가상계좌 정보(은행, 계좌, 입금 기한) | 결제를 준비한다 |
| `confirm` | 대행사 결제 키, 주문 공개식별자, 금액, 멱등키 | 승인 결과(성공, 실패, 금액) | 즉시 결제를 승인한다 |
| `query` | 대행사 결제 키 | 현재 결제 상태와 금액 | 결과를 서버가 직접 확인한다 |
| `refund` | 대행사 결제 키, 환불 금액, 사유, 멱등키 | 환불 결과 | 취소 환불을 요청한다 |

## 보장해야 할 규칙

- 같은 멱등키로 `confirm`과 `refund`를 여러 번 불러도 대행사에서 한 번만 처리되어야 한다. 대행사 멱등키 헤더를 쓰고, 우리 쪽 멱등키 테이블에도 결과를 기록한다.
- `confirm`의 금액은 서버가 저장한 주문 총액이어야 한다. 화면에서 받은 금액을 쓰지 않는다.
- 어떤 입력도 카드번호 원문을 담지 않는다. 로그에는 대행사 결제 키와 공개식별자만 남긴다.
- 대행사 호출이 시간 초과로 끝나면 결과를 알 수 없는 상태로 보고, `query`로 확인한 뒤 처리한다. 확인되기 전에는 재고를 반환하지 않는다.

## 웹훅 (입금 대기 방식의 입금 완료 등)

- **경로**: `POST /webhooks/payments` (로그인 없이 호출되며 사이트 간 요청 위조 방어에서 제외하되 서명으로 인증한다)
- **인증**: 대행사가 주는 서명이나 비밀 값으로 검증한다. 검증에 실패하면 400으로 거절하고 아무 것도 바꾸지 않는다.
- **멱등**: 이벤트 식별자를 멱등키로 쓴다. 같은 이벤트가 여러 번 와도 한 번만 처리하고 항상 200으로 응답한다.
- **검증**: 웹훅 본문을 믿지 않고 `query`로 상태와 금액을 다시 확인한 뒤 반영한다.
- **기한 후 입금**: 주문이 이미 취소됨이면 확정하지 않고 주문을 "확인 필요"로 기록한다.

## 테스트용 가짜 구현이 지원해야 할 시나리오

성공, 실패, 시간 초과(결과 모름), 같은 멱등키 재시도, 금액 불일치, 웹훅 중복, 웹훅 서명 오류, 기한 후 입금.
