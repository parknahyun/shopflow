# 추적 매트릭스: 멀티 판매자 이커머스 핵심 구매·판매 흐름

**관련 이슈**: #3

**기준 문서**: [spec.md](spec.md), [usecase-details.md](usecase-details.md), [tasks.md](tasks.md), [data-model.md](data-model.md), [plan.md](plan.md)

**작성일**: 2026-10-12

요구사항(FR)과 성공 기준(SC)이 어떤 사용자 스토리, 유즈케이스, 테스트 작업, 구현 작업으로 이어지는지 한 곳에서 보는 문서다. 요구사항이 바뀌면 영향받는 작업을 찾고, 작업을 마칠 때 빠진 요구사항이 없는지 확인하는 데 쓴다.

**읽는 순서**: 요구사항 → 사용자 스토리 → 유즈케이스 → 테스트 작업(먼저 작성) → 구현 작업

## 관리 규칙

- 새 FR, SC, UC, 작업을 추가하거나 바꾸면 **같은 PR에서 이 문서도 고친다.**
- 테스트 작업이 없는 요구사항은 "빈틈"(아래 4절)에 올린다. 헌법 원칙 I(테스트 우선)에 따라 비워 둘 수 없다.
- 작업 완료 여부는 [tasks.md](tasks.md)의 체크박스가 기준이다. 이 문서에는 진행 상태를 따로 적지 않는다(두 곳이 어긋나는 것을 막기 위해).
- 작업 번호는 `T###`, 요구사항은 `FR-###`, 성공 기준은 `SC-###`, 유즈케이스는 `UC-##`로 쓴다.

## 4. 빈틈과 주의 (점검 결과)

작성 시점(2026-10-12)에 문서를 대조해 찾은 항목이다. 해소하면 줄을 지운다.

| 번호 | 항목 | 내용 | 조치 제안 |
|------|------|------|-----------|
| G-1 | SC-008 검증 작업 없음 | 신규 고객 10명 중 9명이 도움말 없이 첫 주문을 끝낸다는 기준을 확인할 작업이 없다. 자동 테스트로 잴 수 없다. | 마무리 단계에 사용성 확인 작업을 추가한다(T145의 수동 확인과 묶거나 따로) |
| G-2 | FR-017 직접 테스트 없음 | "정산이 쓸 시각 기록"은 T112, T113에 흩어져 있고, 제외 범위(부분 환불, 반품 환불이 없음)를 확인하는 테스트는 없다. | 제외 범위는 `RestExposureTest`(T012)에서 환불 경로가 취소뿐임을 확인하는 항목을 더하거나, 의도적으로 테스트하지 않는다고 기록한다 |
