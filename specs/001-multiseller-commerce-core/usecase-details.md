## 공통 규칙

모든 유즈케이스에 아래 규칙이 적용된다. 각 유즈케이스에서는 반복하지 않는다.

- **로그인**: 방문자용 유즈케이스(UC-01, UC-02, UC-09)를 제외하면 모두 해당 계정 유형으로 로그인해야 한다. 로그인하지 않았거나 계정 유형이 맞지 않으면 접근이 거절된다. 고객 계정은 판매 기능을, 판매자 계정은 장바구니와 주문 기능을 쓸 수 없다(FR-002a).
- **권한 없는 조회**: 다른 고객의 주문이나 다른 판매자의 하위 주문에 접근하면 존재 여부를 알리지 않고 "찾을 수 없음"으로 응답한다(FR-004, FR-014).
- **멱등 처리**: 결제, 취소·환불, 웹훅 요청은 중복 방지 식별값을 가진다. 같은 값의 요청은 한 번만 처리하고 같은 결과를 돌려준다(FR-009, FR-013b).
- **변경 이력**: 결제, 주문, 하위 주문, 재고 확보의 상태가 바뀔 때마다 이력을 추가한다. 수정과 삭제는 하지 않는다(FR-016).
- **정보 보호**: 카드번호 원문은 저장하거나 기록하지 않고, 개인정보는 기록에 남기지 않는다(FR-015).
- **화면 문구**: 모든 안내 문구는 한글로 쉽게 쓴다.

## 액터

| 액터 | 설명 |
|------|------|
| 방문자 | 로그인하지 않은 사용자. 상품을 보고 가입할 수 있다. |

| 시간 기반 처리 | 정해진 시각에 자동으로 실행되는 시스템 작업. |

## 탐색과 가입

### UC-01 상품 탐색·검색

- **주 액터**: 방문자, 고객
- **목적**: 판매 중인 상품을 찾아보고 상세 정보와 옵션별 재고 상태를 확인한다.
- **사전 조건**: 없음(로그인 불필요).
- **사후 조건**: 데이터가 바뀌지 않는다.
- **기본 흐름**:
  1. 사용자가 상품 목록을 연다.
  2. 시스템이 판매 중이고 승인된 판매자의 상품만 보여 준다.
  3. 사용자가 이름의 일부로 검색하거나 판매자별로 모아 본다.
  4. 사용자가 상품을 선택하면 시스템이 상세와 옵션 조합별 선택 가능 여부를 보여 준다.
- **대안 흐름**:
  - 3a. 검색 결과가 없으면 "결과가 없습니다" 안내를 보여 준다.
  - 4a. 특정 옵션 조합이 품절이면 그 조합만 선택할 수 없게 표시하고 나머지는 선택할 수 있다. 모든 조합이 품절이면 상품을 품절로 표시하고 담기를 막는다.
- **예외 흐름**: 판매 중지, 거절, 정지 상태의 판매자 상품 주소로 직접 들어오면 "찾을 수 없음"으로 응답한다.
- **업무 규칙**: 판매자 정지·거절과 상품 판매 중지는 목록과 검색에서 즉시 반영된다.

### UC-02 고객 가입

- **주 액터**: 방문자
- **목적**: 구매할 수 있도록 고객 계정을 만든다.
- **사전 조건**: 로그인하지 않은 상태.
- **사후 조건**: 고객 계정이 만들어지고 로그인할 수 있다.
- **기본 흐름**:
  1. 방문자가 이메일과 비밀번호를 입력한다.
  2. 시스템이 입력값을 서버에서 검증한다.
  3. 시스템이 비밀번호를 솔트가 적용된 해시로 저장하고 계정을 만든다.
  4. 시스템이 로그인 화면으로 안내한다.
- **대안 흐름**: 없음.
- **예외 흐름**:
  - 2a. 이미 가입된 이메일이면 "이미 가입된 이메일입니다"를 안내하고 계정을 만들지 않는다.
  - 2b. 이메일 형식이나 비밀번호 규칙이 맞지 않으면 항목별로 고칠 점을 안내한다.
- **업무 규칙**: 계정 유형별로 이메일이 유일하다. 같은 이메일로 판매자 계정을 따로 만들 수 있다(계획 문서의 결정).

## 구매

### UC-03 장바구니 관리

- **주 액터**: 고객
- **목적**: 여러 판매자의 상품을 옵션 조합을 골라 한 장바구니에 모은다.
- **사전 조건**: 고객으로 로그인했다.
- **사후 조건**: 장바구니 항목이 추가, 변경, 삭제된다. 재고는 바뀌지 않는다(재고는 결제를 시작할 때 확보한다).
- **기본 흐름**:
  1. 고객이 상품 상세에서 옵션 조합과 수량을 정해 담는다.
  2. 시스템이 판매 중인지와 수량이 1 이상인지 확인하고 항목을 추가한다.
  3. 고객이 장바구니에서 수량을 바꾸거나 항목을 뺀다.
- **대안 흐름**: 3a. 같은 옵션 조합을 다시 담으면 새 항목을 만들지 않고 수량을 합친다.
- **예외 흐름**:
  - 2a. 상품이 판매 중지되었거나 옵션 조합이 품절이면 담을 수 없다고 안내한다.
  - 장바구니를 열 때 담아 둔 상품이 판매 중지되었거나 가격이 바뀌었으면 해당 항목에 변경 내용을 표시한다.
- **업무 규칙**: (고객, 판매 단위)가 유일하다. 수량이 재고보다 많으면 주문을 시작할 수 없다.

### UC-04 즉시 결제로 주문

- **주 액터**: 고객
- **보조 액터**: 결제 대행사
- **목적**: 장바구니의 상품을 카드 등 즉시 결제로 한 번에 주문한다. 재고 선점과 결제 검증이 이 유즈케이스 안에서 함께 처리된다.
- **사전 조건**: 고객으로 로그인했고 장바구니에 항목이 있다.
- **사후 조건(성공)**: 결제가 성공으로 기록되고, 주문이 확정되며, 판매자별 하위 주문(발송 전)이 만들어지고, 재고 확보가 확정된다.
- **사후 조건(실패)**: 주문이 취소됨이 되고, 재고가 반환되며, 결제는 청구되지 않는다.
- **기본 흐름**:
  1. 고객이 주문 확인 화면에서 상품, 금액, 배송지를 확인하고 결제 방식으로 즉시 결제를 고른다.
  2. 고객이 "결제하기"를 누른다. 요청에 중복 방지 식별값이 붙는다.
  3. 시스템이 한 트랜잭션에서 모든 상품의 재고를 판매 단위별로 확보하고(차감), 주문(결제 대기), 판매자별 하위 주문, 결제(준비)를 만든다.
  4. 시스템이 결제 대행사에 결제를 준비하고 고객을 결제창으로 보낸다.
  5. 고객이 결제창에서 결제를 마치고 돌아온다.
  6. 시스템이 결제 대행사에 결과를 직접 조회해 상태, 주문 번호, 금액을 서버에 저장된 주문 총액과 대조한다.
  7. 일치하면 결제를 성공으로, 재고 확보를 확정으로, 주문을 확정으로 바꾼다.
  8. 시스템이 주문 완료 화면에 판매자별 하위 주문을 보여 준다.
- **대안 흐름**:
  - 2a. 같은 식별값의 요청이 이미 처리되었으면 저장된 결과를 그대로 돌려주고 새로 처리하지 않는다.
  - 5a. 고객이 결제창을 닫거나 같은 요청을 여러 번 보내도 결제는 한 번만 일어난다.
- **예외 흐름**:
  - 3a. 재고가 하나라도 부족하면 전체를 되돌리고 부족한 상품을 안내한다. 다른 고객이 결제 중이어서 확보된 재고는 살 수 없다.
  - 3b. 결제를 시작한 뒤 가격이 바뀐 상품이 있으면 고객이 확인한 금액과 달라졌다고 안내하고, 새 금액으로 다시 확인하게 한다.
  - 6a. 대행사 결제가 실패하면 재고를 반환하고 주문을 취소됨으로 바꾼 뒤 실패를 안내한다.
  - 6b. 금액이나 주문 번호가 맞지 않으면 확정하지 않고 오류로 기록한다.
  - 6c. 대행사 호출이 시간 초과로 끝나 결과를 알 수 없으면, 조회로 확인하기 전까지 재고를 반환하지 않는다.
  - 7a. 결제는 성공했는데 재고 확보 유지 시간이 이미 지났으면 주문을 확정하지 않고 "확인 필요"로 기록한다(이번 범위에서는 기록만 한다).
  - 결제가 끝나지 않고 유지 시간(기본 15분)이 지나면 UC-17이 재고를 반환한다.
- **업무 규칙**: 카드번호는 서버를 지나가지 않는다. 결제 결과는 클라이언트 값을 믿지 않고 서버가 직접 조회한다. 한 주문에 성공 결제는 하나뿐이다. 하위 주문 항목에는 주문 당시 단가를 복사해 둔다.

### UC-05 입금 대기로 주문

- **주 액터**: 고객
- **보조 액터**: 결제 대행사
- **목적**: 가상계좌로 입금하는 방식으로 주문한다. 입금 기한 동안 재고를 확보해 둔다.
- **사전 조건**: UC-04의 사전 조건과 같다.
- **사후 조건(입금 완료)**: UC-04의 성공 사후 조건과 같다.
- **사후 조건(기한 만료)**: UC-18이 주문을 취소하고 재고를 반환한다.
- **기본 흐름**:
  1. UC-04의 1~3 단계를 따르되 결제 방식으로 입금 대기를 고른다. 재고 확보 만료 시각은 입금 기한(기본 24시간)으로 정해진다.
  2. 시스템이 대행사에 가상계좌 발급을 요청하고, 은행, 계좌번호, 입금 기한을 고객에게 안내한다. 주문은 결제 대기, 결제는 입금 대기 상태다.
  3. 고객이 기한 안에 입금한다.
  4. 대행사가 입금 완료 알림(웹훅)을 보낸다. 시스템이 서명을 검증하고 이벤트 식별자로 중복을 걸러낸다.
  5. 시스템이 대행사에 상태와 금액을 다시 조회해 확인한 뒤 결제를 성공으로, 재고 확보를 확정으로, 주문을 확정으로 바꾼다.
- **대안 흐름**: 4a. 같은 알림이 여러 번 와도 한 번만 처리하고 항상 정상 응답한다.
- **예외 흐름**:
  - 4b. 알림의 서명 검증에 실패하면 거절하고 아무것도 바꾸지 않는다.
  - 5a. 입금 기한이 지난 뒤에 입금이 들어오면 주문을 확정하지 않고 "확인 필요"로 기록한다.
  - 5b. 입금 금액이 주문 총액과 다르면 확정하지 않고 오류로 기록한다.
  - UC-04의 3a, 3b 예외는 같은 방식으로 적용한다.
- **업무 규칙**: 입금 대기 중인 재고는 다른 고객이 살 수 없다. 입금 기한은 운영 설정으로 바꿀 수 있다.

### UC-06 내 주문 조회

- **주 액터**: 고객
- **목적**: 내 주문과 하위 주문별 배송 상태를 확인한다.
- **사전 조건**: 고객으로 로그인했다.
- **사후 조건**: 데이터가 바뀌지 않는다.
- **기본 흐름**:
  1. 고객이 주문 목록을 연다. 시스템이 본인의 주문만 보여 준다.
  2. 고객이 주문을 선택하면 시스템이 전체 금액과 판매자별 하위 주문의 상태(발송 전, 배송 중, 배송 완료, 구매 확정, 취소), 송장 정보를 보여 준다.
- **대안 흐름**: 2a. 하위 주문 상태에 따라 가능한 행동(취소, 구매 확정) 버튼만 보여 준다.
- **예외 흐름**: 다른 고객의 주문 주소로 들어오면 "찾을 수 없음"으로 응답한다.
- **업무 규칙**: 판매자가 발송 처리하면 1분 안에 고객 화면에 반영된다(SC-007).

### UC-07 발송 전 하위 주문 취소

- **주 액터**: 고객
- **보조 액터**: 결제 대행사
- **목적**: 판매자가 발송하기 전에 하위 주문을 취소하고 전액 환불받는다.
- **사전 조건**: 고객으로 로그인했고, 본인 주문의 하위 주문이 "발송 전" 상태다.
- **사후 조건**: 하위 주문이 취소가 되고, 해당 항목의 재고가 돌아오고, 하위 주문 금액이 전액 환불되며, 환불 거래 내역이 추가된다.
- **기본 흐름**:
  1. 고객이 하위 주문에서 "취소"를 누른다. 요청에 중복 방지 식별값이 붙는다.
  2. 시스템이 하위 주문이 발송 전인지 조건부로 확인하면서 상태를 취소로 바꾼다.
  3. 시스템이 해당 항목의 재고를 판매 단위별로 더한다.
  4. 시스템이 대행사에 하위 주문 금액만큼 환불을 요청한다.
  5. 환불이 성공하면 환불 거래 내역을 추가하고 고객에게 안내한다.
- **대안 흐름**:
  - 한 주문에 여러 판매자의 하위 주문이 있으면 취소한 하위 주문의 금액만 환불하고 나머지는 그대로 진행한다.
  - 모든 하위 주문이 취소가 되면 주문도 취소됨으로 본다.
- **예외 흐름**:
  - 2a. 이미 배송 중이거나 그 이후 상태면 "발송된 주문은 취소할 수 없습니다"를 안내한다.
  - 2b. 고객의 취소와 판매자의 발송 처리가 동시에 들어오면 먼저 처리된 요청만 반영하고 다른 요청은 거절한다.
  - 1a. 같은 취소 요청이 여러 번 들어와도 환불은 한 번만 일어난다.
  - 4a. 대행사 환불이 실패하거나 결과를 알 수 없으면 환불 대기로 기록하고 조회로 확인한 뒤 처리한다. 이 경우 고객에게 처리 중임을 안내한다.
- **업무 규칙**: 환불은 하위 주문 금액 전액만 다룬다. 하위 주문별 환불 합계는 그 금액을 넘을 수 없다. 취소 수수료는 없다. 부분 환불과 발송 후 반품 환불은 이번 범위에서 제외한다(FR-017).

### UC-08 구매 확정

- **주 액터**: 고객
- **목적**: 상품을 받은 뒤 구매를 확정한다. 이 시각이 이후 정산의 기준이 된다.
- **사전 조건**: 고객으로 로그인했고, 본인 주문의 하위 주문이 "배송 완료" 상태다.
- **사후 조건**: 하위 주문이 구매 확정이 되고 구매 확정 시각이 기록된다.
- **기본 흐름**:
  1. 고객이 배송 완료된 하위 주문에서 "구매 확정"을 누른다.
  2. 시스템이 조건부로 상태를 구매 확정으로 바꾸고 시각을 기록한다.
  3. 시스템이 확정 완료를 안내한다.
- **대안 흐름**: 고객이 누르지 않으면 UC-19가 7일 뒤 자동으로 확정한다.
- **예외 흐름**: 배송 완료 상태가 아니거나 이미 구매 확정, 취소인 하위 주문이면 허용되지 않는 변경으로 거절한다.
- **업무 규칙**: 구매 확정 이후에는 상태를 바꿀 수 없다.

## 판매

### UC-09 판매자 가입·입점 신청

- **주 액터**: 판매자(가입 전 방문자)
- **목적**: 판매자 계정을 만들고 입점을 신청한다.
- **사전 조건**: 로그인하지 않은 상태.
- **사후 조건**: 판매자 계정이 만들어지고 입점 상태가 "신청"이다.
- **기본 흐름**:
  1. 판매자가 이메일, 비밀번호, 상호명을 입력한다.
  2. 시스템이 입력값을 검증하고 판매자 계정과 판매자 정보(상태: 신청)를 만든다.
  3. 시스템이 "운영자 승인 후 판매할 수 있습니다"를 안내한다.
- **대안 흐름**: 없음.
- **예외 흐름**: 같은 유형의 이메일이 이미 있으면 가입을 거절하고 안내한다.
- **업무 규칙**: 승인 전에는 상품을 등록할 수 없다.

### UC-10 상품·옵션·재고 등록과 수정

- **주 액터**: 판매자
- **목적**: 상품과 옵션 조합별 가격, 재고를 등록하고 고친다.
- **사전 조건**: 입점이 승인된 판매자로 로그인했다.
- **사후 조건**: 상품과 판매 단위가 저장되고, 판매 중이면 고객 목록에 보인다.
- **기본 흐름**:
  1. 판매자가 상품 이름, 설명, 사진을 입력한다.
  2. 판매자가 옵션(예: 색상, 사이즈)을 정하고, 옵션 조합마다 가격과 재고 수량을 입력한다. 옵션이 없으면 판매 단위 하나만 입력한다.
  3. 시스템이 입력값을 검증하고 저장한다.
  4. 판매자가 나중에 상품 정보, 가격, 재고를 수정한다.
- **대안 흐름**: 4a. 재고를 고치는 동안 결제 중인 주문이 있으면, 이미 확보된 수량은 건드리지 않고 남은 재고만 바꾼다.
- **예외 흐름**:
  - 1a. 필수 정보가 없거나 가격이 0 이하이거나 재고가 음수면 항목별로 안내하고 저장하지 않는다.
  - 1b. 사진이 허용 형식이나 크기를 넘으면 거절한다.
  - 승인 전, 거절, 정지 상태의 판매자는 등록할 수 없다고 안내한다.
  - 다른 판매자의 상품을 고치려 하면 "찾을 수 없음"으로 응답한다.
- **업무 규칙**: 한 상품 안에서 옵션 조합은 중복될 수 없다. 이미 만들어진 주문의 단가는 가격을 바꿔도 달라지지 않는다.

### UC-11 상품 판매 중지

- **주 액터**: 판매자
- **목적**: 상품을 더 이상 팔지 않도록 내린다.
- **사전 조건**: 입점이 승인된 판매자로 로그인했고, 본인의 판매 중인 상품이 있다.
- **사후 조건**: 상품의 판매 상태가 판매 중지가 된다.
- **기본 흐름**:
  1. 판매자가 상품에서 "판매 중지"를 누른다.
  2. 시스템이 상태를 바꾸고 고객 목록과 검색에서 뺀다.
- **대안 흐름**: 이미 결제가 끝난 주문은 영향을 받지 않고 계속 진행한다.
- **예외 흐름**: 장바구니에 담긴 중지 상품은 고객이 주문할 수 없고, 장바구니에서 "구매할 수 없음"으로 표시된다. 결제 중이어서 이미 재고가 확보된 주문은 결제를 마칠 수 있다.
- **업무 규칙**: 판매 중지는 되돌릴 수 있다(상품 수정에서 다시 판매).

### UC-12 내 하위 주문 조회

- **주 액터**: 판매자
- **목적**: 내 상품이 포함된 하위 주문만 보고 처리할 일을 확인한다.
- **사전 조건**: 입점이 승인된 판매자로 로그인했다.
- **사후 조건**: 데이터가 바뀌지 않는다.
- **기본 흐름**:
  1. 판매자가 하위 주문 목록을 연다. 시스템이 본인 판매자 식별자로 걸러 보여 준다.
  2. 판매자가 하위 주문을 선택하면 상품, 옵션, 수량, 배송지, 상태를 본다.
- **대안 흐름**: 상태별로 걸러 보기(발송 전, 배송 중 등)를 할 수 있다.
- **예외 흐름**: 다른 판매자의 하위 주문 주소로 들어오면 "찾을 수 없음"으로 응답한다.
- **업무 규칙**: 같은 주문의 다른 판매자 하위 주문 내용은 보이지 않는다. 판매자의 접근 제한은 서버 권한 검사로 강제한다.

### UC-13 송장 입력

- **주 액터**: 판매자
- **목적**: 상품을 보내고 송장 정보를 입력해 하위 주문을 배송 중으로 바꾼다.
- **사전 조건**: 본인 하위 주문이 "발송 전" 상태다.
- **사후 조건**: 하위 주문이 배송 중이 되고 송장 정보가 저장된다. 다른 판매자의 하위 주문은 그대로다.
- **기본 흐름**:
  1. 판매자가 하위 주문에서 택배사와 송장 번호를 입력한다.
  2. 시스템이 조건부로 상태를 "발송 전"에서 "배송 중"으로 바꾸고 송장 정보를 저장한다.
  3. 고객 화면에 배송 중과 송장 정보가 보인다.
- **대안 흐름**: 같은 주문의 다른 판매자는 각자 따로 발송 처리한다.
- **예외 흐름**:
  - 2a. 하위 주문이 이미 취소되었으면 "취소된 주문입니다"를 안내하고 거절한다(UC-07과 동시에 들어오면 먼저 처리된 것만 반영).
  - 허용되지 않는 상태 변경(예: 배송 완료 후 되돌리기)은 거절한다.
  - 송장 번호가 비어 있으면 입력을 요구한다.
- **업무 규칙**: 택배사 연동은 이번 범위에서 제외하며 송장 정보는 판매자가 직접 입력한다.

### UC-14 배송 완료 처리

- **주 액터**: 판매자
- **목적**: 상품이 고객에게 도착했을 때 하위 주문을 배송 완료로 바꾼다.
- **사전 조건**: 본인 하위 주문이 "배송 중" 상태다.
- **사후 조건**: 하위 주문이 배송 완료가 되고 배송 완료 시각이 기록된다. 아직 구매 확정은 아니다.
- **기본 흐름**:
  1. 판매자가 하위 주문에서 "배송 완료"를 누른다.
  2. 시스템이 조건부로 상태를 바꾸고 시각을 기록한다.
  3. 고객 화면에 배송 완료와 구매 확정 버튼이 보인다.
- **대안 흐름**: 없음.
- **예외 흐름**: 배송 중이 아닌 하위 주문이면 허용되지 않는 변경으로 거절한다. 다른 판매자의 하위 주문이면 "찾을 수 없음"으로 응답한다.
- **업무 규칙**: 판매자가 배송 완료로 바꿔도 정산 기준은 바뀌지 않는다. 구매 확정 시점이 정산 기준이다. 배송 완료 후 7일이 지나면 UC-19가 자동 확정한다.

## 운영

### UC-15 입점 승인·거절

- **주 액터**: 운영자
- **목적**: 입점 신청을 심사해 판매 자격을 준다.
- **사전 조건**: 운영자로 로그인했고 입점 상태가 "신청"인 판매자가 있다.
- **사후 조건**: 판매자의 입점 상태가 승인 또는 거절이 된다.
- **기본 흐름**:
  1. 운영자가 입점 신청 목록을 연다.
  2. 운영자가 신청을 선택해 내용을 확인한다.
  3. 운영자가 "승인" 또는 "거절"을 누른다.
  4. 시스템이 상태를 바꾸고 이력을 남긴다.
- **대안 흐름**: 승인된 판매자를 나중에 정지할 수 있다(정지 판매자의 상품은 고객에게 보이지 않는다).
- **예외 흐름**: 이미 처리된 신청에 다시 처리하려 하면 허용되지 않는 변경으로 거절한다.
- **업무 규칙**: 거절은 종료 상태다. 정지된 판매자의 진행 중 주문 처리는 이번 명세에서 정하지 않았으며 계획 또는 작업 분해 단계에서 정한다.

### UC-16 확인 필요 주문 조회

- **주 액터**: 운영자
- **목적**: 자동으로 처리할 수 없어 "확인 필요"로 기록된 주문을 확인한다.
- **사전 조건**: 운영자로 로그인했다.
- **사후 조건**: 데이터가 바뀌지 않는다.
- **기본 흐름**:
  1. 운영자가 확인 필요 주문 목록을 연다.
  2. 시스템이 기한 후 입금이나 재고 확보 만료 후 결제 성공으로 기록된 주문과 사유를 보여 준다.
- **대안 흐름**: 없음.
- **예외 흐름**: 없음.
- **업무 규칙**: 이번 범위에서는 기록과 조회만 한다. 환불이나 확정 처리는 다음 기능에서 다룬다(FR-017).

## 자동 처리

### UC-17 만료된 재고 선점 반환

- **주 액터**: 시간 기반 처리
- **목적**: 결제가 끝나지 않은 재고 확보를 되돌려 다른 고객이 살 수 있게 한다.
- **사전 조건**: 만료 시각이 지났고 상태가 "유지"인 재고 확보가 있다.
- **사후 조건**: 재고가 더해지고 재고 확보가 반환이 되며, 주문이 취소됨이 된다.
- **기본 흐름**:
  1. 스케줄러가 1분마다 실행되어 만료된 재고 확보를 잠금과 함께 가져온다(다른 실행과 겹치지 않도록 건너뜀 방식을 쓴다).
  2. 시스템이 각 재고 확보의 상태가 "유지"인 경우에만 반환으로 바꾸고 재고를 더한다.
  3. 연결된 결제가 아직 승인 전이면 주문을 취소됨으로 바꾼다.
- **대안 흐름**: 서버가 여러 대여도 같은 재고 확보를 두 번 반환하지 않는다.
- **예외 흐름**: 결제 결과를 알 수 없는 상태(대행사 확인 전)인 주문은 조회로 확인한 뒤에 반환한다.
- **업무 규칙**: 즉시 결제의 유지 시간은 기본 15분이며 설정으로 바꾼다. 반환은 한 번만 일어난다(SC-005).

### UC-18 입금 기한 만료 주문 자동 취소

- **주 액터**: 시간 기반 처리
- **목적**: 입금 기한 안에 입금되지 않은 주문을 정리한다.
- **사전 조건**: 입금 대기 결제의 기한이 지났고 입금이 확인되지 않았다.
- **사후 조건**: 결제가 만료가 되고, 주문이 취소됨이 되며, 재고가 반환된다.
- **기본 흐름**:
  1. 스케줄러가 기한이 지난 입금 대기 결제를 가져온다.
  2. 시스템이 대행사에 상태를 조회해 입금되지 않았음을 확인한다.
  3. 시스템이 결제를 만료로, 주문을 취소됨으로 바꾸고 재고를 반환한다.
- **대안 흐름**: 없음.
- **예외 흐름**: 조회 결과 이미 입금되어 있으면 취소하지 않고 UC-05의 입금 처리 규칙(기한 후 입금이면 "확인 필요")을 따른다.
- **업무 규칙**: 입금 기한 기본값은 24시간이며 설정으로 바꾼다. 입금 기한이 지난 뒤의 입금은 자동으로 확정하지 않는다.

### UC-19 배송 완료 7일 후 자동 구매 확정

- **주 액터**: 시간 기반 처리
- **목적**: 고객이 구매 확정을 누르지 않아도 일정 기간이 지나면 확정해 정산 기준을 만든다.
- **사전 조건**: 배송 완료 후 정해진 기간(기본 7일)이 지났고 상태가 "배송 완료"인 하위 주문이 있다.
- **사후 조건**: 하위 주문이 구매 확정이 되고 구매 확정 시각이 기록된다.
- **기본 흐름**:
  1. 스케줄러가 기간이 지난 배송 완료 하위 주문을 가져온다.
  2. 시스템이 조건부로 상태를 구매 확정으로 바꾸고 시각을 기록한다.
- **대안 흐름**: 그 사이 고객이 이미 구매 확정을 눌렀다면 아무것도 하지 않는다.
- **예외 흐름**: 없음.
- **업무 규칙**: 자동 확정 기간은 운영 설정으로 바꿀 수 있다. 정산 기능은 이 시각을 기준으로 한다.
