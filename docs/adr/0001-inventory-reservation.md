# ADR-0001: 재고 선점 방식

- **상태**: 제안됨 (선점 자체는 헌법이 정했고, 구현 방식은 계획 단계에서 제안한 것이다)
- **날짜**: 2026-10-08
- **관련 이슈**: #3

## 맥락

헌법은 결제 전에 재고를 선점하고(원칙 VIII), 재고 차감과 주문 생성을 원자적으로 처리하라고(원칙 III) 정했다. 재고 1개에 동시 주문 100건이 몰려도 정확히 1건만 성공해야 하고(SC-004), 결제가 끝나지 않으면 재고가 100% 돌아와야 한다(SC-005). 즉시 결제와 입금 대기 두 방식이 있어 선점 유지 시간이 다르다(15분, 24시간).

## 결정

재고 컨텍스트가 소유한 **재고 개체(판매 단위, 즉 옵션 조합마다 한 행)에 대한 조건부 갱신**으로 재고를 차감한다. 같은 트랜잭션에서 재고 확보 행(상태: 유지)을 만든다. 재고 수량은 상품 컨텍스트의 판매 단위가 아니라 재고 개체가 가진다([ADR-0007](0007-context-deployment-strategy.md)).

- 차감: 재고가 요청 수량 이상일 때만 갱신한다. 갱신된 행이 0이면 재고 부족이다.
- 확정: 결제가 성공하면 재고 확보 상태를 확정으로 바꾼다.
- 반환: 결제 실패, 만료, 취소 시 재고를 더하고 상태를 반환으로 바꾼다. 상태 변경은 "현재 상태가 유지일 때만" 조건을 걸어 한 번만 일어나게 한다.
- 만료 처리: 스케줄러가 1분마다 만료된 확보 행을 `SKIP LOCKED`로 가져와 반환한다.
- 유지 시간은 결제 방식별 설정값이다.

## 검토한 대안

| 대안 | 채택하지 않은 이유 |
|------|--------------------|
| 낙관적 잠금(버전 컬럼) | 충돌 시 재시도 코드가 필요하고 동시 요청이 많을 때 실패가 늘어난다. |
| 비관적 잠금(행 잠금 후 읽고 쓰기) | 조건부 갱신보다 복잡하고 교착 가능성이 있다. |
| 레디스에서 선점 관리 | 새 의존성이 생겨 단순성 원칙(IV)에 어긋나고, 데이터베이스와 값이 어긋날 수 있다. |

## 결과

- **좋은 점**: 진실의 원천이 데이터베이스 하나다. 동시성 동작을 같은 종류의 데이터베이스에서 테스트로 검증할 수 있다. 서버가 여러 대여도 같은 행을 두 번 처리하지 않는다.
- **감수할 점**: 재고가 판매 단위 행에 몰려 인기 상품은 행 경합이 생길 수 있다. 확보 후 결제를 포기한 재고는 유지 시간 동안 묶인다.
