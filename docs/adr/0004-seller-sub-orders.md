# ADR-0004: 판매자별 하위 주문 구조

- **상태**: 승인됨
- **날짜**: 2026-10-08
- **관련 이슈**: #3

## 맥락

이 쇼핑몰은 여러 판매자가 입점한다. 고객은 여러 판매자의 상품을 한 번에 결제하지만, 배송, 정산, 환불의 책임은 판매자마다 다르다. 한 판매자의 배송 지연이나 취소가 다른 판매자에게 영향을 주면 안 된다. 헌법 원칙 VII이 판매자별 분리 관리를 요구한다.

## 결정

주문 안에 **판매자별 하위 주문**을 둔다. 배송 상태, 송장, 취소, 구매 확정, 이후 정산과 환불은 모두 하위 주문 단위로 관리한다.

- 결제는 주문 전체 금액에 대해 한 번 일어난다.
- 환불과 취소는 하위 주문 금액 단위로 처리한다. 하위 주문별 환불 합계는 그 금액을 넘을 수 없다.
- 판매자는 서버 권한 검사로 자기 하위 주문만 조회하고 변경할 수 있다. 다른 판매자의 하위 주문에는 "찾을 수 없음"으로 응답한다.
- 고객 화면에는 전체 주문을 한 번에 보여 주고 상태는 하위 주문별로 표시한다.
- 하위 주문 상태 전이는 허용 목록으로 검증한다(발송 전 → 배송 중 → 배송 완료 → 구매 확정, 발송 전 → 취소).

## 검토한 대안

| 대안 | 채택하지 않은 이유 |
|------|--------------------|
| 주문 하나로 통합 관리 | 판매자별 배송 상태, 부분 취소, 판매자별 정산을 표현할 수 없다. |
| 판매자마다 별도 주문을 따로 결제 | 고객이 판매자 수만큼 결제해야 해 구매 경험이 나쁘다. |

## 결과

- **좋은 점**: 판매자 간 영향이 없고 정산과 환불이 판매자 단위로 자연스럽게 이어진다. 접근 제한을 하위 주문의 판매자 식별자 한 곳에서 강제할 수 있다.
- **감수할 점**: 주문과 하위 주문 사이의 금액과 상태 일관성을 유지해야 한다(주문 금액은 하위 주문 합계, 모든 하위 주문이 취소되면 주문도 취소). 결제는 주문 단위, 환불은 하위 주문 단위라 환불 계산이 더 복잡하다.
